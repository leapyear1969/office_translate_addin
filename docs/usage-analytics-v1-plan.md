# 用户使用与 API 统计后台：第一版实施方案

日期：2026-09-10  
最近更新：2026-09-11  
状态：方案草稿，尚未实现埋点、数据库或管理页面。

## 1. 目标与范围

为现有 Word / Outlook 翻译插件建设四个管理页面：使用概览、功能与习惯、API 与成本、质量与故障。第一版保留实际账号标识，管理员可以按姓名、邮箱查询用户使用情况，不做去标识化。

采集用于回答：谁在持续使用、主要使用什么功能、操作能否完成、API 消耗多少、问题发生在哪里。

本期不采集正文、译文、邮件主题、文件名、收发件人、图片、完整 OOXML、令牌或密钥；不做鼠标轨迹、录屏和逐键记录。不增加翻译质量问卷或内容分析。

## 2. 现有代码与接入位置

| 位置 | 当前能力 | 拟增加内容 |
|---|---|---|
| `server/app.js` | SSO 验证；`/api/me`、`/api/detect`、`/api/translate`、`/api/translate/word` | 已验证身份绑定、业务请求统计、事件接收、管理员查询接口 |
| `server/translator.js` | 文本提取、分批调用上游翻译及检测服务 | 在真实上游请求边界统计次数、耗时、字符量及错误 |
| `src/shared/api.ts` | 请求封装、登录和短期会话缓存 | 操作关联 ID、事件批量上报，不在统计记录中保存令牌 |
| `src/taskpane/taskpane.ts`、`src/commands/command-logic.ts` | Outlook 面板与命令入口 | 翻译范围、交付方式、入口、触发方式、最终显示结果 |
| `src/word/taskpane.ts` | Word 翻译、预览、插入、复制、恢复 | 操作结果、结果使用计数、设置变化 |

现有接口响应只保留了有限错误分类。实施时需在后端内部保留标准化上游状态码与失败阶段，不能通过抓取完整请求响应来补充统计。

入口与流程须以当前宿主清单和实际调用路径为准，不能只按 README 或已注册的函数名推断：当前 Word 清单及其生成器中的右键菜单提供“翻译设置”，功能区提供打开面板的入口；代码虽仍注册 `translateSelectionChinese`，当前清单未挂载该直接翻译命令。README 中选区直接替换、只由主动按钮触发等描述也与现有预览刷新路径不完全一致。Word 选区、段落和手动文本当前通过面板预览交付；网页全文翻译写回当前文档正文，桌面全文翻译创建译文副本；Outlook 翻译临时改变邮件正文显示，不修改服务器原始邮件。

## 3. 四个管理页面

### 3.1 使用概览

- 指标卡：新增用户、期间活跃用户、期间成功使用用户、汇总次周留存。期间人数按所选日期及其他筛选条件去重，不将跨多周范围的去重人数称为周活跃，也不默认取最后一周或周平均值代替；留存卡合并成熟首周分组的分子、分母计算，并展示纳入样本量及观察中的样本情况，不平均各周百分比。
- 趋势：每日活跃人数、发起翻译操作数、成功操作数；周活跃和周成功使用另按自然周分组展示，不与期间去重人数混算。日期范围截断自然周时，只统计该周与所选日期的交集并标注“部分周”，不向外扩大取数；未结束的当前周同时说明“本周截至目前”。
- 用户表：姓名、邮箱、租户 ID、首次使用、最近使用、使用天数、操作数、成功操作数；成功操作数只计完整成功，不与包含部分成功的成功使用人数混淆。
- 点击用户可查看其按日用量、功能与语言分布、近期失败操作及实际保留的故障样本。故障计数、操作状态和故障样本是不同记录：不保证每个用户都有样本，有故障计数但无样本时明确显示“未保留样本”，不能显示成“没有故障”；操作明细仍按自身保留规则查询。
- 不把“打开面板”作为核心活跃事件；另行展示面板打开人数。

### 3.2 功能与习惯

- Word / Outlook、桌面 / 网页，以及直接发起翻译的入口分布。翻译入口按直接触发本次翻译的控件、命令或事件归类，不继承最初打开面板的来源；功能区、右键、面板等类别只在对应的直接翻译入口实际存在且可识别时使用。
- 面板打开来源另行统计，不与翻译入口混算；无法可靠识别时记录 unknown。当前 Word 右键打开设置面板、随后在面板中发起翻译时，翻译入口归面板，不记为右键直接翻译。
- 按翻译范围展示操作次数和人数：Word 选区、当前段落、文档正文，Outlook 邮件正文，以及手动文本；宿主与范围分别记录。
- 按交付方式展示操作次数和人数：面板预览、当前文档正文写回、译文副本、临时替换邮件显示。交付方式描述预期路径，不代表已成功，实际结果由状态及成功交付事实判断。
- 翻译范围与交付方式是两个独立、可组合筛选的维度，不将“选区”“段落”“全文”“预览”平铺为互斥功能。一次 Word 选区预览同时具有“选区”和“面板预览”属性，但操作数仍为 1；不同维度的计数不能相加。复制、插入仍单独计为结果使用，不将其改写为新的交付方式或翻译操作。
- 手动与自动触发分布；源语言和目标语言组合。按操作数展示预览语言分布时，目标取最后一轮翻译所请求的语言，源语言取与该轮输入匹配的可信识别结果；没有适用识别依据时源语言为 unknown，不与旧输入的语言拼接，也不把跨轮换过源语言一律归为多语言操作。页面标明操作级归属，各轮 API 用量、成功交付和等待耗时仍保留各自当时语言，不混用统计单位。
- 人均操作次数、使用天数、原文长度区间。
- 复制、插入、查看原文、恢复原文的累计次数。
- 自动翻译模式、目标语言、排除语言等实际存在的设置项，分开展示“所选期间使用人群的最新观测设置分布”与所选日期内用户明确修改并实际生效的设置修改次数、各设置项变更次数。一次修改涉及多项时，修改次数仍为 1，各实际改变的设置项分别计数，两类单位不相加。最新设置分布先按日期及适用筛选条件确定发生过有效使用的用户，再取其对应宿主、设置项的最近观测值；观测时间可以晚于所选期间，不展示为历史期末快照，也不混入所选期间未有效使用的其他账号。
- 设置分布标明人群对应日期、最新观测含义及观测时间／环境，展示人群人数与各设置项的已观测覆盖情况；没有对应观测时标记未观测，不用版本默认值填充。按宿主分别展示实际支持的设置项，不以另一宿主的值代替，也不把不适用的设置当成未观测。Word 设置可能按文档保存，因此最新观测仍不代表用户全部文档的全局偏好；后续新观测可改变这一人群的分布，不表示过去期间的实际设置被改写。

### 3.3 API 与成本

- 分开展示“翻译业务 API 请求数”与“上游翻译服务实际请求数”。前者只包括 `/api/detect`、`/api/translate`、`/api/translate/word` 的实际业务请求，包含自动预检；`/api/me`、`/api/telemetry/batch`、`/api/admin/*` 等认证资料、统计上报、管理查询不混入主指标。上游口径仅包含检测与翻译服务调用，不包含身份认证或用户资料获取调用。
- 上游按检测 / 翻译接口展示请求数、成功数、失败数、请求重试数、修复阶段请求数、提交字符量和耗时。请求重试与修复性重译分别统计，正常分批不计重试；修复阶段请求数按实际请求计，不用修复触发次数代替。上游请求成功以 HTTP 成功状态且响应协议有效为准，不要求译文已通过 Word 结构映射校验；业务校验问题在质量页另行展示。
- 每日趋势及按用户、租户、翻译范围、交付方式、目标语言的用量分布。
- 费用主指标为“参考消耗金额”，按“可计价用量 ÷ 计价单位数量 × 对应生效单价”折算，并标注“按配置单价估算，非账单实付”。单价、币种、计价单位、生效日期由获授权的维护人员通过服务端配置修改，不在第一版管理网页中编辑；按当前有效价格配置中覆盖请求发生时间的规则计价，不能把今天的单价直接套给全部历史请求。价格规则缺失显示“未配置”，不能默认成零。
- 补录或纠正价格配置后，按其生效期间重算受影响的历史参考金额，包括此前因价格未配置而无法计价的部分；历史金额不冻结，也不提供原口径与更正口径两套金额供切换。只对仍保留且计量依据充分的用量重算，计量未知、必要维度缺失或已清理且无法恢复的用量不能因补价而假定可计价；仍缺价格的部分继续显示未配置。价格更正不改变实际请求数、计量用量、计量来源或操作结果。页面展示价格配置更新时间及重算说明，明确历史报表金额可能变化。
- 第一版不模拟免费额度、月度包量、阶梯折扣、超量套餐计算或用户／租户间费用分摊，不构建账单分摊系统。不同币种分别汇总，不隐式换汇或直接相加。
- 原文长度、上游提交字符量、服务商计量与本地计量估算分别命名。不能将 HTML 字符长度或 JavaScript 字符串长度未经规则核对就直接当作计费字符数。
- 每次请求的计价用量按来源选取：优先使用服务商明确返回的可信计量；缺失时，只有适用计量规则已核实且算法已验证，才可用本地估算补充并标记来源。两者不能为同一请求重复相加，也不能将本地估算冒充服务商实测。
- 已确认免计量单独标识，不与计量未知混为一谈。仍无法合理确定计价用量的请求保留为未知，不填零；按当前云区、接口规则核实前，不能仅凭某份公开文档就假定实际部署全部免计量。
- 页面展示已观测请求中的服务商计量、本地估算、已确认免计量及未知来源分布，并区分计量缺失与价格未配置。存在无法计价的部分时，金额标为“已计价部分的参考消耗金额”，同时展示未计价情况，不能冒充完整总额；全部无法计价时不显示为零。
- 计量规则及计价适用性需实施时核对实际 Azure 云区、接口和资源套餐；对无法确定是否计量的失败、请求重试或修复重译请求标注估算限制。请求提交量不等于可计价用量，不能因有提交量就对免计量接口套用翻译字符单价。服务商账单是实际费用的最终依据，参考消耗金额与实付不一致不必然代表采集错误。

### 3.4 质量与故障

本页主故障统计只覆盖插件用户流程，包括 Word / Outlook 登录、自动预检、读取、检测、翻译、备份、显示／写回、复制、插入及恢复等；自动预检即使没有翻译操作也仍在此范围。遥测接收／发送、统计数据库、管理网页登录／查询及统计维护命令的故障不混入主指标，按第 8 节的独立健康日志、数据缺口或页面自身错误提示处理，第一版不为它们增加第五个监控页面。已确认故障、未关联观测及租户／服务级故障视图均遵循此范围；不能通过切换服务级视图把其他系统故障混入插件故障总数。

- 端到端成功率、部分成功率、失败率、翻译受限率及受限次数、无待译内容次数、未确认展示结束次数、取消数、结果未知数；受限原因、无待译内容及未确认展示结束单独展示，不计技术故障。无待译内容和未确认展示结束不进入上述操作结果比率的共同分母，但属于已收到明确终态，纳入结果覆盖率；后者不能被解释为技术显示失败。
- 直接翻译成功操作的端到端耗时 P50 / P95，与预览有效刷新轮次的等待耗时 P50 / P95 分开展示；两者统计单位不同，不能混算一个百分位。业务 API 及上游 API 的耗时也分别展示。
- 按登录、读取、检测、翻译、备份、显示 / 写回、恢复阶段查看故障。
- 错误排行及近期样本：时间、用户（可确认时）、客户端、版本、操作 ID、故障 ID、原始发生阶段、错误分类、状态码。故障主指标为“已确认故障发生次数”，同一次异常在上游调用、业务接口和前端之间的可靠关联传播不重复计数；无法判断是否属于重复传播的报告单列“未关联故障观测数”，不丢弃，也不直接加进已确认故障数。各层失败请求数、失败操作数仍分别统计，不相加为故障总次数；页面说明未关联观测可能重复，不能把已确认数冒充全部实际故障总量。
- Word 跳过段落数和原因；API 成功但显示 / 写回失败的操作数。
- Word 译文结构校验问题单独分类展示，包括上游请求成功后出现的标记或片段映射不匹配；保留真实上游 HTTP 状态，后续修复或最终成功不能抹掉已经发生的校验问题，也不能将其误标为上游 HTTP 请求失败。
- 本页衡量流程可靠性，不将复制率、恢复原文率解释为译文准确率。

### 3.5 公共筛选

四页统一支持日期范围、Word / Outlook、客户端类别、插件版本、租户和用户筛选。语言、翻译范围与交付方式在相关页面补充；后文“功能筛选”指翻译范围与交付方式的单独或组合筛选，不再维护与两者重复、可相互矛盾的独立功能分类。

最新观测设置分布的日期、客户端、版本、功能和语言等适用条件用于圈定使用人群，不据此重建当时的设置快照；按宿主确定该范围内有效使用用户后，读取对应宿主各设置项当前保存的最近观测值。观测自身的时间和环境可以不同于圈定人群的条件，页面须将两者区分，不能把该人群在新版本中观测到的设置称为旧版本当时的设置，也不能因最新观测时间晚于所选截止日就将该用户静默剔除。此人群限定只用于最新设置分布，设置修改次数与设置项变更次数仍按真实生效日期及适用筛选分别统计；两者不是同一时间口径，设置变更本身也不因此成为有效使用。

质量页的“无可验证租户”服务级视图是独立授权的数据范围，不是所有租户管理员均可选择的普通 unknown 分组；不能与指定租户或用户筛选混算归属，其他有意义的公共筛选仍适用。缺省租户筛选也不代表请求或获得服务级权限，具体访问边界见第 9 节。

首次有效使用和首次成功使用按产品级、当前可观测使用历史认定：以同一 `tenant_id + user_oid` 在当前历史中整个 Word / Outlook 插件最早的可观测有效使用、成功使用为准，跨宿主、功能和版本统一维护。筛选不重新计算范围内的首次时间，不能将老用户首次使用另一宿主、功能或版本解释为插件新增用户或重启留存首周；不推断采集上线前未记录的历史使用。本期不以“新增用户”代指“首次使用某功能的用户”。

完整执行统计用户数据删除，或使用历史连同原首用依据已不可恢复丢失后，该账号返回时重新建立可观测使用历史：新的首次有效使用可再次计入新增用户，新的首次成功使用可开启新的留存首周，之后仍按同一历史内的产品级统一认定及筛选规则计算。页面明确“新增用户”表示当前统计历史中首次可观测有效使用的用户，删除或数据丢失后重建可能使其重新起算，不代表用户第一次使用产品。不得额外长期保留旧首用时间或“曾经使用／曾被删除”的个人标记以维持老用户身份，也不得将仍在有效期内的删除执行记录用于新老用户、活跃或留存分析；通过指标说明表达该限制，不承诺逐人识别已被彻底清理的历史。

正常保留期清理明细与日汇总、修改日期或功能筛选、重新登录及服务重启均不重置仍保有依据的首用历史；不能为了简单实现而把每次进入系统或最近一次有数据的日期当成新的首次使用。只有可观测历史及其原首用依据确已清理或不可恢复时，才按上述规则重建，登录资料登记或自动预检本身仍不能开启有效使用或成功使用历史。

次周留存的非日期筛选同时约束首周和次周：对某自然周，分母为产品级首次成功使用发生在该周、且该周至少有一次符合当前筛选条件的成功使用的去重用户数；分子为其中下一自然周至少有一次符合相同筛选条件的成功使用的去重用户数。首周的匹配事件不必是该用户最早的那次成功使用，但必须发生在其产品级首次成功使用周。不筛选宿主时，首周 Word、次周 Outlook 可构成产品留存；筛选 Word 时，次周只有 Outlook 成功使用则不计 Word 范围内留存。客户端、版本、功能、语言等相关筛选沿用同一规则，页面不得把只约束首周人群的产品留存混称为当前范围内留存。

留存的日期筛选选择首次成功使用对应的首周，而不是次周观察周。次周成功使用的查询范围须自动延伸至下一完整自然周，不得被所选日期的截止时间截断；延伸的仅是观察时间，宿主、客户端、版本、功能、语言等非日期条件仍须保持一致。其他指标仍按各自定义在所选日期内统计，留存页面必须分别标出留存首周和次周观察周，不能把两者混作同一时间范围；下一自然周尚未结束时显示“观察中”，不显示为 0% 留存。

日期范围未覆盖完整自然周时，不向外扩展首周样本：仅纳入产品级首次成功使用日期落在所选范围内的用户，再按其所在自然周分组，并应用上述首周与次周的非日期筛选规则。边界分组标注“部分首周样本”，同时展示所选首用日期和所属自然周，不能将其解释为整周全部新增人群的留存。部分首周样本的观察期仍为下一完整自然周，不缩短为与所选星期几对应的部分日期。

概览的汇总次周留存只合并次周观察周已完整结束、且首周样本人数大于零的成熟分组：先按上述首周日期选样和非日期筛选规则计算各分组分子、分母，再以“成熟分组留存人数合计 ÷ 成熟分组首周样本人数合计”求得整体比例。不能等权平均各首周百分比，不能使用期间成功使用人数代替首周样本，也不能仅纳入未成熟分组已经观察到的回访者而遗漏其余分母；未成熟分组须同时排除出汇总比例的两端。

卡片同时展示纳入计算的成熟首周样本人数及分组数，另列截至当前已符合条件、仍在观察中的首周样本情况；各首周留存率、样本量、部分首周标记及观察状态仍可分别查询。有观察中样本但没有成熟样本时，显示“观察中／暂无成熟样本”，不显示 0%；根本没有符合条件的首周样本时显示“暂无首周样本”。已有成熟样本且留存人数为零时，应正常显示 0%。成熟依据自然周观察期是否结束，不额外等待整个迟到接收窗口，也不表示锁定数据；后续合法迟到记录或删除导致的分组变化仍按既定规则修正，不能在新旧首周重复累计同一用户。

时间统一以 UTC 存储，按 Asia/Shanghai 划分统计日和自然周，页面明确时区。筛选后的分母必须与分子使用同一范围；去重人数不能直接累加不同分组的人数。

概览的期间活跃与期间成功使用卡片对整个所选日期范围去重，周活跃和周成功使用仅作为自然周分组指标；周分组取所选日期的交集，不为凑满整周而延伸查询。此处的部分周展示不改变留存专有的首周选样、首周匹配及次周观察规则，不能直接把期间成功使用人数或部分周成功使用展示值当作留存分母。

时间归属按指标对应的事实区分：

- 操作数、成功操作数及操作结果分布、端到端成功率和直接翻译的操作耗时分布，按操作发起时间归属日期；即使跨日完成，也将最终结果计回同一批发起操作，分子和分母不能分别按完成日与发起日筛选。
- 预览刷新等待耗时按各轮翻译触发时间归属日期，并保留该轮当时的维度；不将后续轮次的耗时全部回填到整次预览最早的发起日。成功使用仍按该轮实际交付时间归属日期，不能与耗时样本日期混淆。
- 翻译 / 预览的成功使用按译文实际展示或写回完成时间归属日期；首次成功使用、周成功使用和次周留存沿用此时间，不回溯到操作发起日。
- 复制、插入、查看 / 恢复原文等独立行为，按各自实际发生时间归属日期。
- 上报接收时间只用于判断延迟和数据可靠性，不作为新增使用时间。允许接收的迟到结果更新操作发起日的结果汇总，以及实际交付日的成功使用汇总；涉及首次成功使用变化时，须相应修正留存分组，不能另算一次新操作或新使用。

页面须明确区分“按发起日归属的成功操作”和“按交付日归属的成功使用人数”，两者在跨日、跨周时不要求落在同一天或同一周。操作发起、触发且实际进入处理的新预览刷新轮次、成功交付均可构成有效使用，分别按操作发起、轮次触发、实际交付的日期归属；同一操作可涉及多个使用日，操作数仍只计一次，同一用户同一天有多个此类事实仍只计一个用户日。同一统计范围内，成功使用用户必须包含在活跃用户中。

新刷新轮次的有效使用独立于操作最终状态和成功交付：实际进入处理后即使失败或被后续轮次替代，也保留该轮触发日及当时适用维度的使用事实，不随整次操作最终语言迁移；操作级触发类型仍遵循既定的发起时锁定规则。尚未实际执行、被防抖或排队替换的输入变化，自动预检／空检查，以及同一轮内部的正常分批、技术重试或修复请求不另生成有效使用，不能用实际 API 请求数推算新刷新次数。轮次发起事实仍须满足身份、时间可信度、接收期限及删除边界要求，不靠上报接收时间补造使用日。

| `fault_domain` | 故障所属流程：插件用户流程、统计采集／存储、管理网站、统计维护或待确认；与故障发生阶段、是否关联及租户归属分别记录。共享模块按可可靠确定的调用用途归类，不根据宿主或账号的管理员身份猜测；仅插件用户流程进入质量页主故障汇总 |
| `host`、`client_type`、`app_version` | 宿主、客户端类别、插件构建版本；无法识别时记录 unknown |
| `translation_scope`、`delivery_mode` | 翻译范围与预期交付方式两个独立维度，替代混合的单一 `feature` 分类；分别支持筛选和组合，不表示操作已经成功，复制、插入不改写主交付方式 |
| `entry_point`、`trigger` | 直接发起翻译的入口、操作发起时的手动 / 自动类型；入口不沿用最初打开面板的来源，触发类型按有无明确针对本次翻译的用户动作判断，不按防抖、定时器或异步代码路径判断 |

| `occurred_at`、`received_at` | 事件实际发生时间、服务端接收时间；客户端时钟异常时先依据可靠证据校正，无法可靠校正则拒收该客户端事件，不以接收时间或当前时间代替实际发生时间，也不仅凭其终态或计数部分入库；服务端独立可信时间的记录不受影响 |

| `last_activity_at` | 后端依据关联业务请求及有效客户端事件维护的最后一次可观测真实活动时间，用于无终态超时判断；不得由重复批次、重传或旧事件的当前接收时间续期 |

不信任前端提交的邮箱、租户或用户 ID，身份一律由后端验证后绑定。管理员权限也不能根据前端邮箱判断。

首次 SSO 失败可能没有可验证身份：只计入无身份故障汇总，不猜测用户，不计入已登录用户留存。第一版不为此开放匿名事件入口，因此部分登录前故障不可见，后台需说明此覆盖限制。

无身份不必然意味着租户未知：若后端已有可靠、已验证的租户归属，但不能确认用户，则仍按该租户授权范围展示故障，不编造用户身份；连租户都无法验证的服务端已观测故障及错误观测，归入“无可验证租户”服务级数据范围。不能依据前端提交的租户、未经验证的令牌声明、邮箱或当前查询条件猜测归属，也不为补齐这类数据开放匿名客户端上报。该数据范围与“未关联故障观测”正交：前者描述租户归属，后者描述能否确认独立故障，不能相互替代。

## 5. 采集策略与操作边界

### 5.1 翻译操作

翻译操作从用户明确发起翻译，或系统决定执行翻译时开始，而不是从自动预检或实际发出翻译 API 请求时开始。Outlook 自动预检用于判断是否翻译：检测后源语言等于目标语言、命中排除语言、置信度不足，或处于询问待确认、用户暂不翻译等状态时，不创建翻译操作，也不计有效使用；无需为这些检查增加“无需翻译”的翻译操作终态。系统决定自动执行翻译或用户确认翻译后再登记操作，具体身份绑定仍遵循第 4 节的可验证身份与覆盖限制。

Word 自动跟随在尚无进行中的预览操作时，先读取并确认有待译内容，再决定开始新的翻译操作。普通光标或选区变化引起的自动检查若确认范围为空或仅含无需翻译的空白，不创建操作，不计无待译内容操作或有效使用，也不另行采集自动空检查次数；不能仅因调用了预览入口函数就认定系统已决定执行翻译。此规则同样适用于上一预览已通过复制、插入或其他既定边界结束后的自动检查，不改变用户主动点击翻译空内容仍记无待译内容的规则。检查中真实发生的 API 用量及技术故障照常按自动预检统计，不为关联这些记录而伪造操作。

用户已明确发起翻译后，读取或其他前置处理失败仍属于已发起操作，不能仅因尚未调用翻译 API 而漏计。正常读取后确认用户主动请求的范围为空或仅含无需翻译的空白时，保留该操作并以“无待译内容”结束；发起行为仍构成有效使用，但该结果不计成功使用、技术故障或翻译受限，也不进入端到端成功率等操作结果比率的共同分母，计入结果覆盖率。读取失败、解析异常或存在正文但因安全限制无法处理，不能归入无待译内容；模板占位文字等内容须按实际读取结果判断，不能仅凭宿主暴露的文本为空就认定没有内容。

自动预检本身的实际 API 用量、技术故障照常记录，但不生成失败、取消、翻译受限、无待译内容或 unknown 翻译操作，也不进入翻译操作结果覆盖率的分母。

一次翻译操作保存一行状态记录，不为每个阶段保存一行日志：

1. 发起时创建 `operation_id`，记录开始时间、翻译范围、交付方式、直接发起入口、触发类型和环境；不将最初打开面板的来源继承为翻译入口。
2. 已验证身份后登记开始；后端接到业务翻译请求时也可幂等建立记录。
3. 中间阶段只累计耗时、请求次数、字符量等数值。
4. 前端根据实际处理结果上报终态：预览已有可见交付或成功复制／插入当前有效结果，或直接翻译已获 Office 显示／写回确认时，按请求范围的真实完成程度判定成功或部分成功；整次因安全限制未交付有效译文时判定翻译受限；正常读取确认用户主动请求范围为空或仅含无需翻译的空白，或已有预览按既定统计边界结束时当前范围确认仍为空且无待执行或在途处理，则判定无待译内容；当前预览结果已就绪但未确认展示、也未确认成功复制／插入，且满足约定结束条件时，判定未确认展示结束；未满足成功或部分成功条件的执行异常判定失败；用户主动取消判定取消。无待译内容与未确认展示结束均为独立的非故障终态，不用失败或取消代替，也不能只凭后台 API 成功推断；进行中的预览暂时变空不立即上报终态。
5. 未收到最终结果，且距该操作最后一次可观测真实活动已满 30 分钟时，暂标记 unknown；不固定从最初发起时间计算，持续存在真实活动证据的长预览不因此提前变成 unknown。仅接收实际发生后不超过 7 天的迟到客户端事件，并在关联操作仍处于 30 天明细保留期内时修正操作及重算相关汇总；明细保留期不等于事件允许迟到的时长。

后端以与该操作关联的新业务请求及有效、去重后的客户端事件等实际活动证据更新最后活动时间，不为此要求客户端心跳或逐键上报。计时依据可信或校正后的活动发生时间，而不是旧事件的接收时间；重复批次、事件重传不续期，迟到的旧活动也不能将最后活动时间错误地后推到当前接收时刻。只有登记开始、没有后续活动证据时，从登记的开始活动计算。客户端本地空闲判断与后端缺少观测的判断相互独立，后端暂标 unknown 不等于替客户端确认取消或完成。

后台接口成功不等于显示或写回成功。预览就绪指与当前输入和目标语言匹配、有效且非过期的译文已经写入预览区域并可用；只有能可靠确认宿主任务窗格及当前预览视图可见、该有效译文已经呈现时，才形成预览成功交付，并按首次可确认交付的实际时刻计一次成功使用。后台就绪本身不计成功使用，也不表示整次操作成功；可见交付不要求证明用户已阅读、理解或注视译文。直接翻译仍按既定 Office 显示、写回或副本交付确认规则判断，不把本条预览可见性要求扩展成新的通用阅读跟踪。复制和插入继续按各自实际成功事实统计，不从它们反推此前的预览展示时间。

预览可见性使用可可靠观测的宿主状态及当前预览视图状态，不把仅有控件值或 previewReady 标志当作已可见的证据；无法可靠确认可见时，不猜测已交付。只观察既有生命周期，不为统计额外打开窗格、切换视图、抢占焦点、重译或触发登录，也不增加视线、滚动或持续心跳采集。首次变为可见时仍须校验结果对应当前有效输入、目标语言和轮次，已被新输入或新任务替代的就绪结果不补记交付；同轮已确认交付后的隐藏、重开或重复报告不增加交付事实，重传保持原交付时间与稳定标识。

预览就绪但当前结果始终未获可见交付或成功复制／插入的确认时，不豁免既定空闲结束：无待执行或在途处理并达到空闲期限，由客户端以“未确认展示结束”结算。该状态只描述结算时当前结果的确认情况，不是技术故障、用户取消或无待译内容；保留此前其他轮次的成功使用，不把它解释成整个操作从未被使用。它计入结果覆盖率，但不进入端到端成功率、部分成功率、失败率和翻译受限率的共同分母，单独展示次数，不计入“API 成功但显示／写回失败”的技术故障统计。

未确认展示结束只作用于统计，不关闭面板、不清空就绪译文、不禁用既有结果使用功能，也不新增有效使用。之后当前结果首次获确认展示、复制或插入时，按该新事实的发生时间记录成功使用，不重开、再次结束或仅因后来使用而将原终态改成成功；若合法迟到证据证明同一当前结果在原结束前已经满足完成条件，则按既定窗口纠正原结果，须区分迟到证据与结束后才发生的新行为，不能拿其他历史轮次的交付误作当前结果的完成依据。尚未结束的操作若已成功复制／插入当前有效结果，仍按实际完成程度结算成功或部分成功，不归此状态，也不据此伪造预览可见交付时间。

服务器只有收到有效客户端终态才能登记未确认展示结束；仅有 API 成功、缺少展示事件或客户端失联，不足以推断就绪及结束条件，仍按 unknown 规则处理。客户端恢复执行时，先依据恢复前的真实活动和待处理状态补做应执行的空闲结算，再处理恢复后才发生的首次可见交付，不能用重开后的新显示把本应结束的旧任务重新续期。

待明确：隐藏期间造成的等待耗时如何进入性能统计。不得把等用户重开窗格的时间直接解释为翻译处理耗时，也不能因当前结果就绪就提前计入可见交付的成功等待样本。

预览的成功交付事实与整次操作最终状态分开：先成功展示、后续自动刷新失败时，保留先前成功使用的实际发生时间及当时维度，不撤销已形成的活跃、首次成功使用或留存；后续失败照常统计，整次预览结果按其操作边界独立判定。过期响应、从未实际展示的 API 成功不构成成功交付。不能仅根据操作行最终状态，倒推出整个预览期间是否发生过成功使用；最终状态本身不成功，也不否定另有已确认的成功交付或复制、插入事实。

部分成功按用户请求的翻译范围是否完成判断，而不是按程序是否正常结束判断：已确认完成部分正文翻译，但仍有应翻译正文因安全限制或执行异常未完成时，均计部分成功；空白等无需翻译的内容不参与未完成判定。原因需区分安全限制与执行异常，前者不能作为技术故障累计。现有 Word 跳过段落数可能包含段内部分片段未完成的情况，不能直接解释为整段完全未翻译；采集时需区分整段跳过与段内部分未完成。

预览操作与自动刷新分开计数：符合前述操作发起条件的一次预览形成一个操作，期间输入和目标语言变化引起的自动更新仍归同一操作，累计请求数；每次实际请求保留自己的目标语言维度。整次操作结果按既定结束边界下的当前范围状态及最终有效预览结果判断，范围确认仍为空且无待执行或在途处理时按无待译内容结算；过期响应不计成功，已确认的历史成功交付则按前述规则独立保留。

操作级目标语言取该操作最后一轮翻译所请求的目标语言，每次操作只归一个目标语言分类；最后一轮失败也不退回此前成功轮次的语言，不因切换过语言而一律归“多目标语言”。最后一轮按逻辑刷新顺序判断，不按事件到达顺序判断，迟到旧轮次不能覆盖较新轮次的目标语言。操作级语言变更时，需修正该操作发起日的操作计数与结果归属，不能在旧、新语言分类中各累计一次；各轮 API 用量、成功交付、刷新等待耗时等历史事实仍保留各自当时的语言，不能随操作最终语言迁移。

操作级源语言同样归属最后一轮输入，使用与该输入匹配、已有的可信识别结果，而不是取最早输入、最后一次成功轮次或整个操作期间的语言集合。该轮后续翻译失败时，仍保留已经确认适用于该输入的源语言；只有目标语言变化、原文确实未变且既有识别仍适用时，可以复用已有结果，不为统计重新检测。输入已经变化且没有适用识别依据时必须记 unknown，不能沿用旧输入的源语言或从目标语言、译文是否变化等现象猜测。只有该轮本身确有多个已识别源语言时才记多语言，不能把先后输入中文、英文的两轮当成最后一轮的多语言输入。

源语言识别结果与轮次、输入的关联须有效，过期旧轮结果不得覆盖最新轮的源语言，同一轮已有多源语言依据也不能被单个迟到片段结果覆盖。补齐或修正操作级源语言时，与目标语言一致地修正该操作发起日的语言分类和结果归属，操作总数仍为 1；不能把旧源语言与新目标语言拼成并未对应同一轮输入的操作语言组合。历史请求、成功交付及等待耗时按各自当时的适用语言保存，不随操作级字段迁移；没有可靠识别的部分保持未知，不新增内容分析、输入轨迹或额外检测调用。尚未决定开始新翻译轮次的自动空检查不改变最后一轮归属；没有可用源语言依据的操作仍可记录已明确请求的目标语言，不因源语言未知而隐藏整个操作。

成功复制或插入当前预览译文，是这次预览操作的一个明确结束点；失败的复制、插入不结束操作。结束仅作用于统计归属，不关闭面板、不清空译文。结束后重复复制同一结果只增加复制行为次数，不新增或再次结束翻译操作；之后再次编辑或重新翻译才开始新的预览操作，新操作内的连续自动刷新仍不逐次增加操作数。

仅隐藏或收起任务窗格不结束尚未结束的预览操作，也不代表用户取消翻译；范围和输入未变时，重新打开后沿用原操作。已经结束的操作不因重新打开窗格而重新开始，单纯重开或闲置不新增翻译操作和有效使用；同一已交付结果再次显现也不新增交付。若此前只在后台就绪、从未确认可见交付的有效结果在重开后首次可见，则按该次实际交付时间记录成功使用，不将其解释为打开动作本身构成活跃，也不为此另建翻译操作或再次结束已结束的操作。隐藏本身不取消已发出的上游请求，真实 API 用量仍照常统计；真正关页且未收到最终状态时，按结果缺失规则处理，不能把隐藏事件直接当作取消或关页结束信号。

同一预览范围内，尚未结束的操作因普通光标或选区变化而经正常读取确认暂时变空时，仅暂停生成结果，不立即结束、不计取消，也不新增操作。空闲期限内恢复有待译内容且未发生其他既定结束边界时，继续原操作；切换翻译范围或明确重新开始仍按新操作规则处理。自动空检查本身不构成新的有效使用或翻译相关活动，不重置客户端 30 分钟空闲计时，不要求新增空检查事件或心跳。当前范围变空后，旧译文不再是对应当前输入的有效结果，过期响应不构成新交付；此前已确认的成功交付、实际 API 用量及技术故障仍保留，不能因最终无待译内容而抹掉。

预览空闲结束：连续 30 分钟没有翻译相关活动，且没有待执行或在途的相关处理时，由客户端依据当前已确认的范围与结果结束并上报当前操作。当前范围经正常读取确认仍为空或仅含无需翻译的空白时，以无待译内容结束；当前有效译文已就绪但尚未确认可见交付或成功复制／插入时，以未确认展示结束；当前已有可见交付或成功使用依据时，按其真实完成程度结算，不凭其他历史轮次的成功代替当前结果。读取失败或当前范围状态无法确认时，不能猜测为空或就绪。单纯隐藏、重开或保持面板打开不作为新的翻译活动，也不豁免空闲结束；不得为此增加持续心跳、逐键记录或输入轨迹上报。客户端定时器被宿主暂停时，恢复执行后依据真实活动及待处理状态补做空闲判断，不将重新显示面板当成重新开始计时的依据。

空闲结束仅是统计边界，不关闭面板、不清空译文、不产生新的有效使用；结束后的重复复制仍只计行为，再次编辑或重新翻译才建立新操作。须区分操作统计结束时刻与译文实际处理完成、交付时刻，不将空闲等待直接计入翻译耗时，也不把成功使用时间移到空闲结束时。成功结算必须依据当前有效结果的可见交付或成功复制／插入确认，并按请求范围的真实完成程度区分成功与部分成功；不能只凭其他历史轮次曾成功或仅凭就绪就推断最终成功。客户端关页或上报未送达时，后端仍按 unknown 规则处理，允许后续收到有效终态后修正。

切换翻译范围并发起新任务，或明确重新开始翻译时，创建新操作；同时只对当前执行上下文中被替换且尚未结束的旧预览操作结算，不影响其他文档、窗格、客户端或宿主中的独立操作，也不再次结算已经结束的操作。结算依据必须在旧预览被失效或清空前取得，反映其当时状态：

- 当前有效结果已有可见交付或成功复制／插入确认，且没有更新的待执行或在途处理时，按真实完成程度结算成功或部分成功，不伪造预览展示事实。
- 当前有效结果已就绪，但无该结果的可见交付或成功复制／插入确认，且没有待执行或在途处理时，按未确认展示结束结算；不将“已就绪但未确认展示”混作仍在处理的取消或技术失败。
- 当前处理已经明确失败、翻译受限，或当前范围已确认无待译内容且没有待执行／在途处理时，保留对应终态，不因换任务而统一改为取消。
- 当前仍有待执行或在途处理，因本次明确离开／替换而被放弃时，计取消；不能借用此前轮次的成功或失败代替尚未完成的当前结果，也不计技术失败或等待结果缺失超时。

旧操作的统计结束与新操作的发起是两个事实，不要求必定同时发生。当前 Word 点击“文档正文”视图会使旧预览失效，即使尚未点击全文翻译，也应按上述状态结束被明确放弃的旧预览，但不能仅因切换视图就创建全文翻译操作或新增有效使用；新操作仍须满足用户明确发起或系统决定执行的条件。单纯隐藏／收起任务窗格继续遵循不结束预览的既定规则，不能把所有隐藏或每次预览失效都当作任务替换；同一任务内部的正常刷新与暂时空选区也不按本条结束操作。

切换时刻只是旧操作的统计结束边界，不把此前已发生的交付时间改成切换时刻，也不将阅读或切换等待计入翻译耗时。历史成功使用、故障及实际 API 用量独立保留；统计上取消不表示已经中止上游请求，切换后到达的旧响应仍按有效性规则处理，不能仅因 API 成功而重开或追改已确定的取消结果。

用户主动重试失败操作产生新操作并关联上一操作 ID，旧操作保留失败结果，不将明确的失败改成取消；网络层重试仍归原操作。

预览性能按刷新轮次统计：每轮从触发翻译处理到该轮有效译文实际展示，形成至多一个成功等待耗时样本；过期或未展示的响应不进入成功样本，重复展示同轮结果不重复采样。后续有效刷新与首轮同等参与预览等待耗时分布，不只取整次操作的首次结果；失败等待耗时另计，缺失耗时不能填零。整次预览的阅读时间、结果使用等待和空闲结束等待不作为刷新耗时，不把多个有效轮次增加为多个翻译操作。预览的轮次耗时不与直接翻译的操作端到端耗时、业务 API 耗时或上游 API 耗时混算。

### 5.2 API 用量

- 翻译业务 API 统计采用明确的接口白名单：`/api/detect`、`/api/translate`、`/api/translate/word`。认证资料请求、遥测上报、管理查询不作为用户的翻译业务用量；如另有运维请求统计，须与此主指标分开标识，不能因管理员查看报表而增加翻译业务请求数。
- 上游翻译服务请求仅计实际检测、翻译调用；SSO 令牌交换、Graph 用户资料等认证相关调用不得混入上游翻译请求数、提交字符量或翻译费用估算。
- 上游请求结果与业务可用性分层：HTTP 为成功状态且响应可按约定协议解析、必需字段完整时，计该上游请求成功；HTTP 非成功、协议无法解析或必需响应字段缺失等计请求层失败，并保留实际可获得的 HTTP 状态。Word 译文标记、顺序或片段映射校验不通过属于业务校验问题，不把一个协议正常的成功请求追改为上游失败；修复重译及最终 Office 交付结果另行判断，实际请求次数和提交量均照常计入。
- 在真正发出上游请求的位置计数，不能用按钮点击数或路由访问数代替。
- 自动预检即使未产生翻译操作，其实际业务 API 请求和上游检测请求仍参与各自用量汇总；不要求每个请求都有 `operation_id`，不能为了关联用量而伪造翻译操作。接口层接到请求但未实际调用上游时，不增加上游请求数。
- 每个请求的尝试次数、成功 / 失败、耗时和提交量均参与汇总，包含失败请求；请求重试只在失败后确实再次尝试该请求时计数，正常分批不算重试。
- 修复性重译单列：Word 既有标记不匹配或疑似未翻译规则触发的重译，按实际发出的修复阶段请求累计，不将一次修复触发简单记为一次 API 调用，也不将这些请求一律算作请求重试。当前已核查的上游调用链没有网络、超时或 HTTP 错误后的自动重发，但已有业务修复重译，实施时不得将两者混淆。
- 请求用途与是否重试是不同属性：修复阶段若将来确实实现请求失败后的重试，该次请求既属于修复阶段，也属于请求重试。修复阶段请求数与请求重试数不能直接相加当作额外调用总量；全部请求总数始终按每次实际请求计一次。当前阶段无相关自动重试时，对应重试数为 0，不能为统计而新增重试行为。
- 成功请求不长期保存独立明细，按小时、真实用户、宿主、客户端、版本、接口、翻译范围、交付方式、目标语言聚合。
- 上游翻译服务 API 汇总与翻译业务 API 汇总分开保存，不相加为同一个调用总量；自动预检可产生翻译业务与上游检测请求，但仍不因此产生翻译操作。
- 计量来源独立于请求成功或操作终态记录：服务端从真实上游响应读取可信计量，或按已验证规则计算本地估算，保留来源、计量单位及适用规则信息。请求失败、超时或修复重译是否可合理计价需按适用规则判断，不能仅因有提交量就假定全部可计价，也不能仅因请求失败就假定免费。前端事件不得覆盖上游计量或其来源。
- 小时与日汇总分别保留服务商计量用量、本地估算用量、已确认免计量请求及计量未知请求的数量和来源信息；同一请求用于金额计算时只选取一个有效计量依据，不重复相加。来源覆盖只描述已观测请求，不能借此声称进程崩溃等造成的未观测请求也已被完整覆盖。
- 用量统计由服务端负责，前端关页不会丢失已完成的上游用量记录。
- 耗时保存固定桶直方图、样本数、总耗时；长期百分位由桶合并估算，标记为近似值，不能平均每日 P95。

### 5.3 低价值事件

- 复制、插入、查看 / 恢复原文：本地按实际成功行为累计增量，批量上报后合并到用户日计数。成功复制或插入当前预览结果可同时结束对应预览操作，但行为计数与操作数是不同口径，不能相加为翻译操作总数；重复使用同一结果不重复结束操作。
- 预览刷新发起：只在新轮次实际进入翻译处理时确认其发起事实，以稳定轮次标识去重，按实际触发日期及该轮当时维度合并到用户日汇总，用于有效使用、期间／周活跃及使用天数。该轮失败仍保留发起事实，不新增翻译操作，不因此计成功使用或成功等待样本；已执行后过期与从未执行的候选输入须区分，后者不计。只保留相应汇总及必要幂等依据，不长期保存逐轮成功明细或输入轨迹。
- 预览成功交付：仅在能可靠确认窗格及当前预览视图可见、对应输入和目标的有效译文已呈现时，按同轮首次交付时刻和当时维度保留成功使用事实，幂等合并到用户日汇总；后台就绪不计交付，不因后续刷新失败而回撤，不为每次交付新增翻译操作，也不保存输入变化轨迹或正文。重复显现同轮已交付结果不重复累计，首次成功使用取已确认成功使用事实的最早时间，不只取操作最终状态对应的时间，也不回填到后台就绪时刻。
- 预览等待耗时以刷新轮次区分和去重，按轮次触发日期及当时维度合并为固定桶直方图、样本数和总耗时，不长期保存逐轮成功明细；与直接翻译操作耗时桶分别保存。跨日、跨分组查询合并桶估算 P50 / P95 并标注近似，不平均各日百分位。
- 设置：按真实账号、宿主和实际设置项保留最近观测值、观测时间及必要来源环境；设置变更只统计用户明确修改且实际生效的改变，按真实生效日期累计，不存逐次操作轨迹或历史状态快照。初始化读取、切换文档、自动回填或重复上报导致的观测差异不生成用户设置变更，同值重复设置也不增加次数。最近观测以可信或校正后的实际观测时间认定，旧观测迟到不覆盖较新值；观测更新与用户变更独立，不能根据后端最近快照前后不同就反推用户进行了修改。最新值只用于所选期间使用人群的最新观测设置分布，不能用于还原所选末日的设置状态。
- 设置变更依据实际生效的差异，不用保存按钮点击数、dirty 标志或保存回调次数代替。对需统一保存的表单，提交前改动后又恢复到原有生效值，保存时没有实际差异则不计变更；若两次修改已经先后生效，即使最终回到原值，也不能仅因最新值相同就抵消已经发生的变更。明确未生效的修改不计成功变更；已经生效的设置不能因随后自动预检失败而撤销变更事实，相关用户流程故障另计。记录设置变更不生成翻译操作或有效使用，统计写入失败也不回滚用户实际设置。
- 设置计数保留两种单位：一次用户明确修改或保存提交生效，且至少一个设置项真实改变时，设置修改次数加 1；该次实际改变的每个设置项分别加 1，未变项不增加。一次保存同时改变目标语言和自动模式时，修改次数为 1、两项各变更 1 次，设置项变更合计为 2，两种计数不能相加或混称为用户操作次数。排除语言等列表型设置作为一个设置项，同次提交改变多个列表内容也只计该项一次，不按语言条目数扩大设置项变更数。
- 两种计数可由同一成功变更事件聚合，使用稳定修改／事件标识幂等更新，不能在逐项处理时把一次修改重复累计多次；多个独立已生效修改也不能因批量发送而合并成一次。只保留相应用户日汇总和必要去重标记，不增加逐次修改日志或历史设置快照；最新观测值仍独立维护，没有实际变化或未生效时两类计数均不增加。这些计数均不加入翻译操作数，也不把设置修改本身变成有效使用。
- 面板打开按会话去重计数；会话 ID 仅用于技术去重。可靠可识别的打开来源单独记录，无法识别则为 unknown，不把它复制为后续翻译操作的入口。
- 不采集普通按钮点击、滚动、鼠标移动、输入内容或持续心跳，也不为 Word 新操作前发现空内容的自动检查新增诊断计数或行为埋点。

### 5.4 故障

先按所属流程区分插件用户流程与统计／管理支持流程，再应用独立故障与未关联观测的计数规则。不能因为故障发生在 Word 任务窗格、同一 Node 服务或共用登录／请求封装中，就直接归入插件主故障指标；遥测请求失败与插件登录失败、管理网页登录失败与 Office SSO 失败必须区分。共用接口或模块需保留可可靠确定的调用用途，来源不足时保持来源待确认并作健康／覆盖说明，不强行归入插件用户流程；来源待确认、故障未关联和租户未验证是不同维度。

故障所属流程的分类不改变实际请求或操作结果：翻译是否成功仍依据 Office 的真实交付，不能因支持系统故障被排除出主故障数而把实际失败的翻译改成成功，也不能因遥测或管理页面失败就把正常翻译改成失败。

插件用户流程中的技术故障按独立发生次数计入主故障汇总；安全限制导致的整次翻译受限或部分成功另行汇总原因，无待译内容及未确认展示结束另行计数，均不计技术故障。同一次异常能够可靠关联时，在上游调用、业务接口和前端的传播仅算一次故障，不因包装成不同层的错误类型或重复报告而增加次数。上游失败请求数、翻译业务接口失败请求数、失败操作数仍各按自身单位统计，不能把这些层的计数相加作为故障发生次数；再次请求或后续独立执行又失败则属于新的故障，不能仅因同一操作、相同错误码或时间接近而合并。

关联信息缺失、无法可靠判定报告是独立异常还是已有故障传播时，作为未关联故障观测单独汇总，不忽略，也不通过新生成一个故障标识就将其当作已确认独立故障。已确认发生的故障照常计数；未关联观测具有稳定观测标识，可复用其事件 ID，重传同一观测不得重复累计。观测计数使用实际观测时间和已知报告位置，不伪造无法确认的原始故障时间或阶段；能验证的用户、租户和请求身份仍保留，不能因为故障未关联就将其改成无身份记录。只有取得可靠关联证据，才可在允许接收和修正范围内调整归类；调整须幂等修正原计数，不能一边仍将该报告作为未关联，一边重复增加已存在的独立故障。

页面并列展示已确认故障发生次数与未关联故障观测数，并说明后者可能与前者或其他观测重复，不能直接相加。存在未关联观测时，不得仅因已确认故障数为零就显示“未发生故障”；故障关联覆盖不足与故障身份未知是不同问题，也不能因为出现错误报告就生成额外失败操作或有效使用。

实施时在实际故障发生位置建立 `fault_id`、`fault_occurred_at` 及原始阶段，在相关错误响应与客户端报告中传播允许的关联字段；这些是拟新增能力，不假定当前错误封装已完整携带。后续捕获、包装或上报同一异常沿用原故障标识与实际发生时间，不创建新的故障；故障标识不能替代身份校验，前端报告不能改变服务端已确认的用户归属、原始阶段或真实上游状态。故障发生的时间及阶段归属取原始发生事实，而非最后一个报告位置；业务接口自身的 HTTP 状态仍与上游状态分开保留。

故障计数的幂等保障独立于故障样本：同一故障的不同传播事件可能有不同 `event_id`，仍须按已验证归属及 `fault_id` 去重，不能只靠事件 ID 或检查样本是否存在来防重。去重凭据须覆盖该故障允许被接收的完整窗口，新增故障计数与去重标记采用一致的持久更新；抽样淘汰或明细清理不能使相同故障重新累计。传播报告不得重写原始故障时间以延长接收窗口；新的操作终态可以按其自身时间处理，但其中关联的旧故障不能因此再计一次。

故障明细按“小时 + 租户 + 宿主 + 客户端 + 插件版本 + 原始发生阶段 + 错误码”最多留 20 条样本，额度可配置。同一已确认故障的传播报告不重复占用样本额度；未关联观测如保留样本，沿用相同限额规则并明确标记为观测，未知原始阶段保持 unknown，已知报告位置另行标明，不能据此反推原始故障位置。页面分别显示已确认故障数、未关联观测数及各自保留的样本数，不将任何样本数或报告条数当作已确认独立故障总数；两类样本占用同一分组的限额时不能各自再获得一份重复额度，不长期保存所有观测明细。

上述样本额度保持跨用户分组，不增加每用户保底，也不额外保存每用户最近若干条故障明细。用户详情只查询实际保留的样本，并同时展示该筛选范围内的已确认故障与未关联观测计数；计数大于零而无样本时，明确说明未保留样本，可能未抽中或已超出样本保留期，不能据此推断无故障或用户未使用，也不能自动把抽样未留明细当作采集丢失。仍在保留期内的操作结果独立查询，不受样本额度限制；不能把全部中间故障明细转存到操作行或其他数据集，变相提供未选择的逐用户样本保底。

错误明细仅保存字段白名单，不保存原始异常消息、响应正文、认证头或带查询参数的完整 URL。自动预检技术故障照常汇总与采样，明确属于检查阶段且可没有翻译操作 ID；不能为记录该故障而新增一条失败翻译操作。译文结构校验问题按业务校验阶段及白名单原因记录，即使后续修复成功也保留该问题的发生事实；不得将业务校验失败伪造为上游 HTTP 失败，上游真实状态为 200 时应保留 200，并与后端业务接口自身的响应状态区分。

## 6. 统计口径

| 指标 | 第一版定义 |
|---|---|
| 新增用户 | 当前可观测使用历史中的产品级首次可验证有效使用发生在所选日期范围内；首次时间跨宿主、功能和版本统一认定，不随筛选、登录或普通保留期清理重置。完整删除或原首用依据不可恢复丢失后重建历史，可再次计入；不是安装数、注册数或用户真实终身首次使用人数，具体见第 3.5 节 |
| 有效使用 | 发起翻译 / 预览、触发且实际进入处理的新预览刷新轮次，取得成功或部分成功结果，或成功执行复制、插入、查看 / 恢复原文；操作发起按发起时间，新刷新按该轮触发时间，成功交付按实际展示 / 写回完成时间，独立行为按实际发生时间认定。新轮次即使失败仍可构成有效使用，但不新增操作或成功使用；排除单纯开面板、闲置、登录刷新、自动预检、未执行就被替代的输入变化，不把内部重试、正常分批或修复请求本身另算新的有效使用 |
| 期间活跃 | 所选日期范围及其他筛选条件内至少发生一次有效使用的去重账号数；跨日、跨周按同一账号去重，不累加日活或周活，不取最后一周或周平均值代替 |
| 期间成功使用 | 所选日期范围及其他筛选条件内至少发生一次成功使用的去重账号数，包含部分成功；沿用成功使用事实的实际发生日期，跨日、跨周去重，不用按发起日归属的成功操作数代替 |
| 周活跃 | 按周一至周日的自然周分组，对该周与所选日期范围交集内发生有效使用的账号去重；边界不足整周标记“部分周”，未结束当前周标记“本周截至目前”，不向外扩大日期，也不用于替代期间活跃卡片 |
| 成功使用 | 翻译取得成功或部分成功结果，预览发生有效成功交付，或成功复制 / 插入译文；部分成功纳入成功使用，但不因此成为成功操作。历史预览成功交付不因后续刷新失败而撤销；受限、无待译内容、未确认展示结束、失败、取消和 unknown 状态本身不构成成功使用，也不能否定独立确认的历史交付或复制、插入事实 |
| 周成功使用 | 按自然周分组，对该周与所选日期范围交集内至少发生一次成功使用的账号去重，包含部分成功；边界不足整周及当前未结束周分别明确标注，不向外扩大日期，不用各周人数相加或平均代替期间成功使用 |
| 次周留存 | 日期筛选选择首周样本：仅纳入当前可观测使用历史中的产品级首次成功使用日期在所选范围内、且首周符合当前非日期筛选的用户，按其首次成功使用自然周分组；下一完整自然周在同一范围再次成功使用的人数 / 该首周样本人数。完整删除或原首用依据不可恢复丢失后重建历史可开启新的首周，不恢复已清理首用档案。边界周不扩大样本，标注“部分首周样本”；具体见第 3.5 节，部分成功可开启或满足留存，未观察完下一周时显示“观察中” |
| 汇总次周留存 | 对按既定日期及非日期条件选出的、有样本的成熟首周分组，合并留存人数与首周样本人数后相除，不平均各周百分比；次周未结束的分组不进入分子或分母，单独展示截至目前的观察中样本。无成熟样本不显示 0%，有成熟样本而无留存才显示 0%；各首周明细仍保留，成熟不等于数据冻结，具体见第 3.5 节 |
| 端到端成功率 | 成功操作数 / 已知结果操作数；此处已知结果分母仅含成功、部分成功、失败、翻译受限，排除无待译内容、未确认展示结束、取消和 unknown；受限代表存在待译需求但未完成，必须保留在分母中。无待译内容及未确认展示结束虽是明确终态，仍不进入该分母，须单独展示，不能把此比例解释为全部已登记操作的成功占比 |
| 部分成功率 | 部分成功操作数 / 已知结果操作数；部分正文已确认完成，但其余应翻译正文因安全限制或执行异常未完成，两类原因分开统计；空白等无需翻译的内容不影响结果等级 |
| 翻译受限率 | 翻译受限操作数 / 已知结果操作数；整次因安全限制未交付有效译文，不计成功、部分成功或技术故障；单独展示受限次数与原因 |
| 无待译内容次数 | 用户主动发起翻译后正常读取确认请求范围为空或仅含无需翻译的空白，或已有预览按既定统计边界结束时当前范围确认仍为空且无待执行或在途处理的操作数；保留原操作及此前已形成的有效使用，终态本身不新增有效使用或成功使用，不计技术故障或翻译受限，不进入成功率、部分成功率、失败率及翻译受限率的共同分母，不撤销独立确认的历史成功交付。新操作前的自动空检查不计入，进行中的预览暂时变空也不立即计入 |
| 未确认展示结束次数 | 当前有效预览结果已就绪、尚无该结果可见交付或成功复制／插入的确认，且满足既定结束条件时由客户端明确结算的操作数；按操作发起日归属，纳入结果覆盖率，但不计成功、失败、取消或技术故障，也不进入端到端成功率等共同分母。只描述结束时当前结果的确认情况，不否定其他历史成功使用；之后新发生的展示或使用不追改该终态，合法迟到证据对原事实的纠正另按既定规则处理 |
| 结果覆盖率 | 已收到最终状态的操作数 / 已登记操作数；最终状态含成功、部分成功、失败、翻译受限、无待译内容、未确认展示结束和取消，unknown 单独展示；未确认展示结束须有有效客户端终态，不能由后端超时或仅有 API 成功推断 |
| 已确认故障发生次数 | 插件用户流程中已确认的独立技术异常发生次数，按原始发生时间及阶段归属；同一次异常的可靠关联传播和重复报告只计一次，新的请求尝试或后续独立执行再次失败另计。同一操作可有多个故障，最终成功不抹掉已发生故障；不等于失败请求数、失败操作数或各层报告数之和，无法判断是否重复的观测不直接纳入 |
| 未关联故障观测数 | 插件用户流程中已收到但无法可靠判定是独立故障还是重复传播的错误观测数，按实际观测时间归属并对同一观测去重；单独展示，不直接与已确认故障数相加，也不忽略。未关联不等于身份未知，不据此新增失败操作或有效使用；取得可靠证据后的归类修正不得产生重复贡献 |
| 参考消耗金额 | 按适用规则选取的计价用量 ÷ 计价单位数量 × 当前有效价格配置中覆盖请求发生时间的单价；服务商计量优先，缺失时允许已核实规则下的本地估算，明确标记来源，未知不填零。补录或纠正价格后按生效期间重算仍有充分计量依据的历史金额，不冻结旧金额、不改写用量事实。按币种分别汇总，不模拟套餐分摊；价格规则缺失显示“未配置”，存在未计价部分时明确只代表已计价部分，标明非账单实付及配置更新、历史重算情况 |
| 设置修改次数 | 用户一次明确修改或保存提交实际生效且至少一个设置项真实变化时计 1 次，按真实生效日期及适用筛选统计；一次修改涉及多项仍只计 1，没有实际差异、初始化观测或未生效的尝试不计，不属于翻译操作数 |
| 设置项变更次数 | 按实际设置项分别累计生效变化，同次修改改变两项则两项各计 1；列表型设置同次改变多个内容仍只计该设置项一次。各项合计表示字段变化量，不表示修改提交次数，不与设置修改次数相加；不长期保存逐次修改轨迹 |
| 人均操作次数 | 同一筛选范围的翻译 / 预览操作数 / 发起这些操作的去重用户数 |
| 人均使用天数 | 范围内有效使用用户日数 / 有效使用用户数 |
| 直接翻译 P50 / P95 | 直接翻译成功操作的端到端耗时百分位，以操作为单位；失败耗时另计，缺失耗时不得填零，不混入预览会话时长或刷新轮次耗时 |
| 预览等待 P50 / P95 | 所有有效交付刷新轮次从翻译触发到实际展示的等待耗时百分位，每轮至多一个成功样本；不只取每次操作的首次结果，过期、未展示或缺失耗时不进入成功样本，失败等待耗时另计；按固定桶估算时标注近似 |

自动翻译和手动翻译均纳入总量，但页面必须可分开查看。故障用户、取消操作和结果缺失不能被静默隐藏。

操作触发类型按是否存在明确针对本次翻译的用户动作认定，而不是按代码是否自动调度认定：用户点击翻译、确认翻译或在待译输入区主动提交文字属于手动，后续使用防抖或异步处理不改变这一性质。Outlook 自动询问后由用户确认的翻译计手动，按“始终翻译”设置自行处理新邮件计自动；Word 普通文档选区变化引起的跟随翻译计自动，在翻译面板主动输入待译文字引起的翻译计手动。操作级 `trigger` 在新操作发起时确定，不因其内部后续自动刷新或网络层重试改写；它描述操作如何发起，不表示整个过程从未有人参与，也不是每轮技术调度次数。

## 7. 存储与数据量控制

初版建议单实例 Node 服务使用本地持久磁盘上的 SQLite，使用事务、WAL 与版本化迁移；多实例部署前改用共享数据库。此为拟选方案，尚未增加依赖。

第一版不备份统计数据库，不生成或保留用于恢复统计数据的数据库导出、恢复副本或磁盘快照；部署时须核对主机、磁盘及云平台的自动备份范围，不能在应用层不备份、却由整机快照隐含保留统计库。本地持久磁盘与 WAL 属于在线持久化和事务恢复机制，不等于另有灾难恢复备份，也不能据此承诺磁盘损坏后可恢复历史。此决定仅针对使用统计数据库，不修改现有 Word 文档原文备份、译文副本或恢复功能。

| 表 / 数据集 | 内容 | 保留时间 |
|---|---|---|
| users | 真实身份、姓名、邮箱、当前可观测使用历史中的产品级首次有效 / 成功使用、最近使用；首次时间跨宿主、功能和版本统一维护，不随查询筛选或普通保留期清理重算，完整删除或原首用依据不可恢复丢失后按第 3.5 节重建；只有登录或自动预检的账号可尚无首次有效 / 成功使用，不能用身份登记时间或检测请求时间填充，不另存已清理的旧首用档案 | 存续账号保留；执行统计用户数据删除时移除，不以仅删除此表代替完整清理 |
| operations | 一次操作一行，终态更新，包含累计性能和用量 | 30 天 |
| api_usage_hourly | 翻译业务 API 与上游翻译服务 API 分层的小时用量与耗时桶，保留请求重试数、修复阶段请求数，以及服务商计量、本地估算、已确认免计量和未知来源的独立用量／请求统计；不混入认证、遥测或管理请求 | 30 天 |
| user_activity_daily | 每用户每维度按各自事实日期归属的行为、操作结果、新预览轮次发起事实与用户日计数，分别保留设置修改次数及按设置项的变更次数，以及分开保存的直接翻译操作耗时桶和预览刷新等待耗时桶；用于去重、留存和长期性能查询，新轮次不增加操作数，设置计数不使该行为成为有效使用 | 12 个月 |
| api_usage_daily | 翻译业务 API 与上游翻译服务 API 分层的日汇总与耗时桶，沿用小时汇总的重试、修复阶段及各计量来源分类，保留长期解释和计价所需的计量单位、适用规则信息；不混入认证、遥测或管理请求 | 12 个月 |
| faults_daily | 仅汇总插件用户流程，分开保存已确认故障发生次数与未关联故障观测数：前者按原始发生日期和阶段归属，后者按实际观测日期及已知报告位置归属，保留可确认的真实用户、公共筛选维度和白名单错误分类；不以观测数替代故障数，不与样本条数混算，也不因存在错误记录就认定用户有效使用 | 12 个月 |
| error_samples | 插件用户流程中已确认故障与未关联观测的限额白名单样本，明确区分类别并沿用同一跨用户分组额度，不提供每用户保底；同一故障传播或同一观测重传不重复占用额度 | 14 天 |
| user_preferences | 每真实账号、宿主及实际设置项的最近观测值、观测时间和必要来源环境，用于所选期间有效使用人群的最新设置分布；不保留历史状态快照，不用旧观测的迟到接收覆盖新值 | 当前最近观测值，执行统计用户数据删除时移除 |
| event_receipts | 批次、事件及故障发生的幂等标记，区分标记种类，不能用不同传播事件的 event_id 代替 fault_id 去重 | 自首次接收后至少保留 7 天，且不得早于对应事件或故障允许接收窗口结束时清理；超过接收时限的旧发生事实不再重放 |
| deletion_fences | 最小删除执行记录：真实账号键、删除截止时刻及清理期限；仅用于执行删除、阻止旧事件和被删操作回报重建历史，不包含姓名、邮箱、首用时间、使用明细或统计计数，不进入行为分析 | 覆盖相关旧事件及旧操作仍可被接收或修正的完整窗口，确认其已不能合法重新建档或回补后清理；不直接套用 event_receipts 的 7 天清理期限，不无限期保留 |

日汇总应保留用户和所有公共筛选维度，才能跨天和跨宿主准确去重。按用户聚合的数据仍属于可关联个人的数据，并非匿名汇总。

统计用户数据删除的在线库范围已经确定：按真实 `tenant_id + user_oid` 清理该用户的 `users`、`operations`、`api_usage_hourly`、`user_activity_daily`、`api_usage_daily`、`faults_daily`、可关联的 `error_samples`、`user_preferences` 及 `event_receipts` 等记录，并同步修正所有派生汇总、报表和缓存。只删除姓名、邮箱或用户表一行不算完成；同邮箱的其他租户账号不能被误删，无法归属该用户的无身份故障也不能通过猜测删除。

不为被删用户另存匿名总量或去标识化副本以维持原报表数字；该用户对历史活跃、留存、操作、故障、API 用量和参考金额的贡献随删除移除，相关人数、分母、分子及金额须一致重算。接受历史统计因此变化，页面明确历史数据可能因删除调整，不将这种预期变化误报为采集故障、未使用或费用计量错误。普通保留期清理明细仍遵循“先汇总再删除”，不能与此处主动删除用户全部可关联在线统计数据的范围混淆。

此处的删除对象是统计数据，不是 Entra 账号，也不表示给该账号设置停止未来采集的开关。第一版不保留统计数据恢复备份，不建设从备份恢复已删除用户后再次清理的流程。部署检查若发现统计库已被自动快照或其他恢复副本覆盖，应明确报告其与本方案不符，不能宣称没有备份，也不能在未检查和确认的情况下直接删除这些副本。

为防止迟到上报重建已清理历史，允许将 `deletion_fences` 作为完整删除的唯一保留例外：仅保存必要账号键、由服务端确定的删除截止时刻及清理期限，不保存姓名、邮箱、首用历史、行为计数或被删除数据副本。该记录仍是可关联个人的数据，限删除执行与接收校验使用，不供普通报表查询，也不用于判断用户新老、计算活跃或留存。删除后的正常新使用不因该记录而停止采集，也不能因此提前移除删除边界、重新允许旧记录入库。

最小删除执行记录的建立、关联数据清理及汇总修正须具有一致的删除边界；删除过程中及之后的并发统计写入均须校验该边界，不能因请求已经在途或持有清理前缓存而绕过。数据库不可写或删除未完成时，不得报告删除成功。执行记录覆盖旧事件仍可接收及被删操作仍可能产生合法迟到回报的完整窗口；其清理期限须有明确有限上界，并与 7 天事件接收、30 天操作明细及修正规则一致，不能直接照搬 7 天事件回执清理策略。清理前须保证接收规则已无法重建该边界内的旧操作或历史，后端幂等建档也不能把旧操作的真实发起时刻改成新请求或接收时刻来重新登记。旧事件重传或正常新使用不延长此期限，新的明确删除请求可建立新的删除边界。

每日执行清理；先确认汇总成功再删除明细。延迟终态需更新对应日期汇总，采用可重算或差量修正机制，避免重复累加。

长期 API 用量汇总须保留按请求发生日期及价格适用规则重新计价所需的用量、计量单位、来源及维度，不能只保存初次折算出的金额，也不能以成功请求明细已清理为由拒绝对仍可合理计价的日汇总补价。若缓存或物化参考金额，价格补录、更正后须使受影响期间的旧计算结果失效并重新计算；同一报表结果不能混用更正前后的价格配置。价格配置更新时间与重算说明应可供页面展示，重算不得回写或伪造实际请求、用量及计量来源。

容量示例：每天 1 万次翻译、每条操作约 1 KB，30 天约 300 MB 原始操作数据，另计索引、汇总、故障样本与在线 WAL 等开销，不另计本期不建立的统计备份。上线后以实测行大小和维度数量修正估算，并监控数据库大小、写入延迟和清理任务。

## 8. 上报与可靠性

- 前端缓冲达到 20 个事件或 15 秒时尝试发送；隐藏或关闭时尽力刷新，但不承诺送达。
- 只在已有有效会话时发送，不为统计弹出登录、不保存令牌到持久队列。
- 未发送队列仅保留内存，有大小与重试上限；断网或关页可能丢失前端行为，页面明确这是可观测数据而非审计账本。
- 批次携带稳定 ID，后端以已验证用户加事件 ID 去重；重复发送不会增加复制次数等计数。
- 客户端事件仅在实际发生后不超过 7 天时接收，以可信或校正后的事件发生时间判断，不按操作开始时间判断，也不因重传而刷新发生时间。超过窗口的事件不再回补行为、成功使用或操作结果，并以不含内容的拒收计数展示该覆盖限制；不能将拒收解释为用户未使用。关联操作仍在 30 天明细保留期内，是修正操作的另一项必要条件，不表示可以接收已发生 30 天的旧事件；及时上报的新终态可修正较早发起但仍保留的操作。
- 事件幂等标记自首次接收后至少保留 7 天，且必须覆盖对应事件完整的允许接收窗口；窗口边界的接收与清理使用一致规则，不能出现仍允许重传、去重依据却已清理的空档。
- 统计用户数据删除的截止边界优先于普通迟到接收规则：截至该时刻已发生且应被清理的旧事件，即使仍在 7 天接收窗口内、事件回执已经删除，也不得重新写入。被删除操作的迟到终态不得重新建立原操作或补回已删除历史；前端关页后重开、重传批次或上报时换用当前接收时刻均不能绕过删除。删除后独立确认发生的新使用与新业务请求仍按各自事实时间正常统计，不因沿用旧结果或携带旧操作关联就恢复被删操作的发起记录、历史交付或累计值，也不凭空新增翻译操作。前后端所有相关写入路径均须遵守同一边界，不只过滤遥测批次入口。
- 接收端使用枚举和数值范围白名单、请求体大小上限、事件时间上限和限流；不允许客户端覆盖上游用量。
- 客户端时钟异常时，先依据可靠时间证据校正；无法可靠校正实际发生时间的客户端事件按事件整体拒收，不采用仅保留终态、计数或耗时等字段的部分接收方案，也不把接收时间／当前时间改写为发生时间后重新上报。校正后的时间仍须满足 7 天接收窗口、操作保留及删除截止等既定规则，校正不能成为绕过这些边界的手段。同一批次中其他独立且合法的事件仍可正常处理，不能仅因一个事件时间不可信就丢弃全部合法事件。
- 被拒收的时间异常事件不用于创建或更新操作状态、最后活动时间、行为计数、用户首用时间、活跃、留存或耗时汇总；已有合规登记的操作若没有其他有效终态，仍按最后一次可信活动后的超时规则暂标 unknown，不能凭被拒收报告中的“成功”修正。拒收的是统计事件，不是翻译业务请求；服务端有独立可信时间和依据的实际业务／上游请求记录与用量仍正常统计，不因客户端时间异常而删除或改写。
- 时间异常拒收仅记录无内容的规范原因、拒收计数及必要覆盖提示，属于统计接收质量问题，不另计插件用户流程故障，也不把缺失解释为用户未使用。可用接收时间衡量拒收与采集健康情况，但不能将其用作用户行为发生时间；明确反馈拒收结果，避免在没有有效校正依据时持续重传同一不可接收事件。校正不得为统计额外触发登录或阻塞翻译，健康信息仍遵循第 8 节的范围与数据白名单。
- 统计入口与翻译请求使用独立限额，避免批量上报消耗当前 `/api` 业务限流配额。
- 用量更新采用持久事务，不只放进程内计数器；数据库不可写时翻译仍继续，输出无内容的健康告警与缺口起止时间，后台标记数据不完整。
- 统计与管理系统自身的问题通过独立健康日志、数据缺口标记或管理页面自身错误状态呈现，不写入插件用户流程的主故障计数，也不生成翻译操作、有效使用或成功使用；第一版不为此新建独立监控页面。插件自身登录与自动预检故障仍属用户流程，不能因尚无翻译操作而排除；管理网页登录和查询错误则不因此成为插件登录或翻译故障。
- 遥测入口、统计数据库或其错误处理链路失效时，不通过同一失效管道再次上报自身故障，不递归触发故障写入；使用有界、避免刷屏的健康输出及可恢复时的数据缺口说明。独立健康信息仍遵守字段白名单和无正文、无令牌、无原始异常消息的限制，不能借换名为健康日志长期另存用户行为或绕过既定删除范围。服务级故障只读授权不自动授予这些支持系统日志的访问权；管理页面只提供本次请求的安全错误提示及必要的通用数据覆盖说明。
- 进程在上游响应后、统计落盘前崩溃仍可能产生少量缺口，需结合服务商用量与账单核查；实际费用以账单为准，不宣传严格的计费审计能力。核查时必须区分采集缺口与免费额度、套餐、折扣等造成的口径差异，不能仅凭参考消耗金额与实付金额不同就判定数据丢失。
- 第一版没有统计数据库备份，接受磁盘损坏、数据库文件不可恢复丢失等故障可能导致历史统计永久丢失。故障后可修复服务并在必要时重新建立统计库，但不承诺恢复丢失的历史记录；服务商账单也不能代替缺失的用户行为、身份维度或操作结果。后台须标明可确认的数据缺失及重建后的可观测数据起点，不能将丢失期间显示为已确认的零使用，也不能把重建后的首次观测冒充用户真实历史首次使用。30 天、12 个月等保留期是正常运行时的清理规则，不是无备份条件下的数据可恢复性保证。

## 9. 管理接口与访问

拟增加管理路由 `/admin/usage`、`/admin/features`、`/admin/api`、`/admin/errors`。

对应查询接口为 `/api/admin/overview`、`/api/admin/features`、`/api/admin/api-usage`、`/api/admin/errors`、`/api/admin/users`；事件入口为 `/api/telemetry/batch`。路径为实施约定，不表示已经存在。

管理后台采用普通浏览器独立访问的网站形式，管理员直接访问 `/admin/...`，不要求先打开 Word / Outlook 插件或在 Office 任务窗格中查看后台。

管理网页登录采用标准 Entra 授权码 + PKCE 流程，取得面向本后端 API 的委派访问令牌。后端沿用并验证签名、发行者、受众、有效期、`tenant_id + user_oid` 及所需 API 权限；当前验证要求包含 `access_as_user`，不能用 Graph 访问令牌或登录 ID Token 代替本 API 令牌。若沿用 `/api/me` 获取资料，还须验证 OBO 与 Graph 用户 ID 一致性及 `User.Read` 同意。

当前 `OfficeRuntime.auth.getAccessToken()` 只用于 Office 插件环境，不搬到普通浏览器管理站；管理端取令牌流程与插件登录解耦，不将 Office SSO 失败自动导向管理网页登录，也不为翻译统计额外弹出管理登录。现有 `consent.html` 和 `/auth/consent/callback` 仅处理 Graph 权限同意，不建立管理网页登录会话，不能当成已经实现的后台登录；如管理场景需要复用同意能力，应正确返回管理站，且不破坏现有 Office 同意流程。

第一版使用服务端配置的 `tenant_id + user_oid` 管理员白名单。管理员仅能查询配置的租户范围；跨租户查询权限需单独配置。普通用户不可访问管理页面数据，查询接口逐次校验身份、管理员资格和授权数据范围；不能因为 Entra 登录成功、拥有目录管理员身份或前端显示管理员界面就放行。独立网站只是访问形式，不替代这些权限检查。

无可验证租户故障数据增加独立的服务级只读授权，仅对服务端配置中额外明确授予该资格的后台账号开放，默认不授予；即使账号可以查询多个租户，也不因此获得该范围。授权仅包含无可验证租户的故障汇总、未关联故障观测及限额样本，不自动开放任何已验证租户的数据，更不附带删除或改价权限；仅有此授权的账号仍须另获租户查询授权才能读取对应租户数据。

质量与故障页通过独立选择的服务级视图展示“无可验证租户”数据，沿用有意义的日期、宿主、客户端、版本等筛选，不与某租户或某用户的筛选混作同一归属，也不默认混入租户故障总数。由管理查询接口逐次校验此独立授权，汇总、排行、样本及其直接读取路径使用同一规则；不能因未指定租户筛选就返回全部服务级数据，或只在前端隐藏视图而仍把数据包含在响应中。未获授权的账号不返回此范围的记录、计数或样本，可仅展示通用的查询覆盖范围说明，不透露该范围实际有无记录。

第一版管理网页及 `/api/admin/*` 仅提供查询，不增加用户统计删除、价格编辑或其他维护写接口，也不在网页中建立维护角色或自助维护流程。管理员白名单只授予查询资格，不能被当作删除或改价授权；隐藏维护按钮不是权限边界，不得存在可凭同一查询令牌直接调用的维护入口。

统计用户数据删除由明确获得服务器／部署维护授权的人员，通过受控服务端维护命令执行。执行前须明确核对目标 `tenant_id + user_oid`、授权范围、删除截止时刻及对历史报表的影响，并确认删除；维护命令必须执行统一的删除边界、最小删除记录、关联数据清理及汇总修正规则，不能以手工只删用户表代替。执行未完成不得报成功，第一版没有统计备份，不能承诺可撤销。

价格由获授权的维护人员通过服务端配置渠道修改，校验配置后按既定生效期间重算规则生效；网页仅展示适用配置、配置更新时间和重算说明，不提供编辑能力。服务端维护资格与后台查询白名单相互独立，不通过新增 Office 登录或扩大浏览器令牌权限来取得维护能力。

部署时须配置并验证浏览器客户端注册、SPA / Web 类型与对应流程、准确回调地址、暴露的 API scope、委派权限及同意、支持的租户与云区，以及 issuer / audience。管理页与 API 的部署须满足同源限制；如需不同来源，应另行明确受信来源配置，不能为登录便利放开任意 Origin。真实注册信息及回调地址以部署配置为准，不填入虚构账号、应用或密钥；访问令牌可通过受保护 API 的鉴权请求头传递，但不得成为统计事件载荷字段，也不写入统计数据库或故障样本。

姓名、邮箱只存用户表，页面按需关联，避免每条事件重复保存。数据用途和保存期限在插件中可见。

第一版不提供行为统计关闭选项，按本方案规定的范围统一采集个人行为、服务运维与 API 用量数据；不设计账号级或客户端级的统计开关，也不设置因用户关闭统计而停止采集、排除分析或处理历史数据的分支。相关业务术语见根目录 `CONTEXT.md`。

统一采集不代表数据完整送达：断网、关页、登录前不可观测故障及数据库写入失败仍可能造成缺口，后台必须展示覆盖限制，不能把缺失记录解释为用户未使用。

## 11. 验收标准

- 一次全文翻译产生 20 次正常分批上游请求时，操作数为 1、实际上游请求数为 20、请求重试数为 0，不能把第 2—20 批当作重试。
- 1 次首轮请求返回后触发业务修复，修复阶段实际产生 3 次请求且没有失败重发时，实际上游请求数为 4、修复阶段请求数为 3、请求重试数为 0；操作数仍为 1。若未来修复阶段实现失败重试，该请求在总请求数中只计一次，修复与重试两个属性不能相加重复计算全部或额外调用数。
- 上游 HTTP 200 且响应协议完整、但 Word 译文标记不匹配时，该请求计上游成功，同时保留业务校验问题及真实 HTTP 200，不将其追改为上游失败；修复重译的每次实际请求另计，最终操作结果依据 Office 实际处理结果判定。HTTP 200 但响应协议无法解析或必需字段缺失时，仍应计请求层失败，不能仅凭状态码判成功。
- 一次上游请求失败导致业务接口失败并由前端报告，同一异常的关联信息完整时，独立故障发生次数为 1，同一故障最多占用 1 条样本额度；上游失败请求、业务失败请求及失败操作仍分别按各自单位计数，不能相加成 3 次故障。传播报告具有不同 event_id 或经过重复上报，仍不得增加该故障的发生次数，原始故障时间、阶段和真实上游状态不被包装层覆盖。
- 再次实际请求又失败，或业务结构校验问题触发修复后修复请求又独立失败，应分别计新的故障，即使属于同一操作、具有相同错误码或发生时间接近；最终操作成功也保留已确认发生的故障。未保留样本、样本被淘汰或清理不影响故障总次数，同一故障不能因此再次累计；迟到操作终态不得把关联旧故障改成当前新故障。故障计数与其幂等标记一致落盘，不能因多层同时上报而重复累计。
- 后端已确认 1 次独立故障，另收到 1 份无法判定是否属于该故障传播的前端报告时，展示已确认故障数 1、未关联故障观测数 1，不能相加宣称发生 2 次独立故障，也不能丢弃前端报告。重传同一观测仍只计 1；即使用户、错误码和时间接近也不能强行合并。该前端报告的用户或租户已验证时，仍按已知身份保留，不改成无身份故障。若只有未关联观测、没有已确认故障，不得显示“未发生故障”；后续在允许范围内取得可靠关联证据并修正时，不能重复增加已确认故障或保留已经解决的未关联贡献。
- 用户翻译已成功，随后遥测上传失败、统计数据库不可写或管理员查询报表报错时，原翻译结果不变，不增加插件主故障数或失败翻译操作；支持系统问题通过健康日志、缺口或页面自身错误提示体现，不新增监控页面。统计管道失效不能递归经自身上报错误。插件 SSO、自动预检、复制／插入／恢复等用户流程发生的真实技术故障仍进入对应主统计，管理网页登录或查询失败不能冒充插件登录故障；不能根据共用模块、Word 宿主或管理员身份直接猜测所属流程，也不能因为排除支持系统故障而掩盖实际失败的翻译操作结果。
- 同一小时、同一既定样本分组中，100 个用户各有一次已确认且合法接收的独立故障，额度配置为 20 条时，该组保留样本总数不得超过 20，故障汇总仍计 100，各用户的故障计数不因未抽中而丢失。没有样本的用户详情显示相应故障计数及“未保留样本”，而不是“没有故障”；不追加每用户最近 5 条或其他保底样本。仍在保留期内的失败操作可独立查询，样本过期或未抽中不删除操作结果，也不将抽样未保留自动判为采集缺口。
- 一次 `/api/translate` 请求计 1 次翻译业务 API 请求，实际产生的上游调用另计；随后登录资料查询、遥测批次上报及管理员多次刷新后台均不增加该翻译业务请求数。`/api/detect` 即使只用于自动预检也纳入翻译业务请求数；SSO、Graph 等认证调用不进入上游翻译请求数或翻译费用估算。
- 自动预检实际产生 100 次上游检测请求、但均未决定执行翻译且用户未确认翻译时，记录 100 次上游检测用量，不因此产生翻译操作、有效使用、活跃或留存。自动预检故障单独保留，不伪造失败操作；用户已明确发起翻译后发生读取失败则仍计入该翻译操作的失败结果，不能以尚未调用翻译 API 为由漏记。
- Word 上一预览已经结束，用户未主动发起新翻译，只在空段落或空选区间移动光标时，自动跟随检查不产生新的翻译操作、无待译内容操作、有效使用或成功使用，也不额外记录自动空检查次数；确认有待译内容并决定自动翻译后才建立新操作。检查实际发生的 API 请求及技术故障仍分别统计，技术故障不能伪装成空内容；同样的空范围若由用户明确点击翻译，则按主动操作的无待译内容规则记录。
- Outlook 自动询问后点击确认翻译计手动，按“始终翻译”设置处理新邮件计自动；Word 在待译输入区主动输入文字触发的防抖翻译计手动，普通文档选区变化带来的跟随翻译计自动。后续自动刷新、异步处理或网络重试不改写所属操作最初的触发类型，也不因此新增操作。
- 用户通过 Word 右键打开设置面板、随后点击面板中的选区翻译入口时，该操作的 `entry_point` 为面板；只有可靠观测到的打开行为才将 `panel_open_source` 记为右键，否则为 unknown。不能将面板后的全部翻译继承为右键翻译，也不能把当前清单未挂载的直接翻译命令当作现有入口。

- 在授权范围内执行某一 `tenant_id + user_oid` 的统计用户数据删除后，在线库中该用户的资料、偏好、操作、可关联故障样本、事件回执及小时／日汇总均不可再查询，派生报表和缓存同步移除其贡献；不能仅删除姓名、邮箱或用户表。仅允许保留规定用途和期限内的最小删除执行记录，该记录不进入用户报表、活跃、留存或新老用户分析。历史活跃、留存、操作、故障、API 用量及参考金额随之重算，不另留匿名总量维持旧数字，同邮箱不同租户的账号及其他用户的数据不受误删。普通明细到期清理仍保留规定期限内的日汇总，不能与完整统计用户数据删除混用；部署不得通过未声明的自动快照或恢复副本继续保留本期明确不备份的统计库。
- 用户 11:58 成功交付、12:00 执行统计用户数据删除、12:01 才收到 11:58 的事件时，不得因事件仍在 7 天窗口内或去重回执已清理而重建历史。被删操作的迟到终态及清理前已在途的统计写入同样不得补回应清理的数据；后端不能用当前接收时间给旧操作重新建档。删除后独立发生的新操作、成功使用或实际业务请求仍正常统计，不解除对旧记录的拒收，也不恢复旧操作累计值。删除未完成或存储不可写时不报告成功；删除执行记录到期清理后，相关旧数据仍不能绕过接收与操作保留规则重新入库。
- 某账号第 1 周曾有效且成功使用，第 3 周完整执行统计用户数据删除，第 5 周重新有效且成功使用时，旧首用档案及旧贡献不恢复，按新可观测使用历史将其计为第 5 周新增用户，并以第 5 周为新的留存首周；页面解释这不是用户真实首次使用产品。删除执行记录即使仍存在，也只能拒收旧数据，不能据此将该账号认作老用户或沿用已删除首用时间。若只是正常清理明细／日汇总、改变筛选、重新登录或重启服务，且原首用依据仍保留，则不得重启新增与留存；仅登录或自动预检也不能开启新的有效／成功使用历史。
- 无权限账号不能读取管理接口；租户范围隔离有效。拥有管理员查询资格的账号也不能通过网页或 `/api/admin/*` 删除统计数据或修改价格，第一版不开放维护写路由，不能仅依赖前端隐藏按钮。
- 只获某租户或多个租户查询权限、未获服务级故障查询权限的管理员，不得通过省略租户条件、请求 unknown 分组或直接读取样本取得无可验证租户的记录、计数或样本。额外获得服务级只读授权后，可在独立视图查询该范围，但不能由此读取未授权的已验证租户数据或执行维护；仅获服务级授权也不自动获得任何租户数据权限。租户已可靠验证而用户未知的故障仍按对应租户授权处理，租户无法验证时不能依靠前端声明猜测；故障是否未关联与租户是否可验证分别判断，不为展示补开匿名事件入口。
- 获授权维护人员通过服务端受控命令删除统计数据时，须核对并确认真实租户、账号、截止时刻和影响范围，命令统一执行删除边界与关联清理；不存在备份可恢复或网页撤销的承诺。价格通过服务端配置修改并按生效期间重算，网页仅反映新的查询结果、配置更新时间和说明；查询管理员白名单不自动授予维护资格。
- 管理员可在没有 Office / OfficeRuntime 环境的普通浏览器中独立登录并访问授权后台；登录使用面向本 API、具备所需委派权限的令牌，Graph 令牌或 ID Token 不能冒充本 API 令牌。Graph 同意完成不等于管理登录完成，也不等于获得管理员权限；现有 Word / Outlook 登录和授权流程不因新增管理站而被改成网页登录。
- 客户端时钟偏差导致事件时间落到未来，且缺少可靠校正依据时，拒收该事件，不用接收时间代替，不因载荷带有成功终态或有效计数就部分入库，也不更新操作最后活动时间。已有合规登记的操作若始终缺少有效终态，按规则暂标 unknown；服务端可信时间的实际 API 请求与用量照常保留，翻译不受影响。后台反映时间异常拒收及覆盖限制，不将其算成插件技术故障或确认用户未使用；同批合法事件仍可接收。存在可靠校正依据时，按校正后的实际时间继续验证普通接收、保留和删除边界，不将所有客户端时钟偏差一律拒收，也不借校正把应拒收的旧数据当作新数据。
- 统计断网、数据库写入失败、队列满时翻译仍可运行，监控能反映缺口。
- 清理明细后，过去月份的活跃、留存、公共筛选与近似耗时分布仍可查询；此要求不意味着无备份的统计库在存储彻底损坏后仍可恢复。
- 在隔离测试环境模拟统计库不可恢复丢失后，只验证服务可修复并重新开始采集，不要求恢复历史；后台明确缺失范围或可确认的覆盖起点，不将丢失历史显示为零，也不宣称拥有未建立的恢复能力。部署检查确认统计库未纳入数据库导出、磁盘／整机快照或其他恢复副本；现有 Word 原文备份与恢复功能不受本决定影响。
- 新增自动测试覆盖去重、聚合、真实请求计数、权限、数据字段过滤、保留期清理与统计用户数据删除；结合项目现有测试、类型检查和构建验证。
- 在真实 Word / Outlook 中验收复制、插入、恢复、自动翻译、SSO 失败和关页缺失等行为；自动测试不能替代宿主验收。
