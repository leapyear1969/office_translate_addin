# Word Online 翻译限制

网页版所有翻译入口（包括右键翻译）都检查整份正文及各类页眉、页脚；放行文字、基本格式和普通矩形表格（包括空单元格）。正文全文翻译包含正文表格文字，页眉和页脚仅检查并保留，不参与翻译。桌面端翻译流程不受此限制，恢复原文入口不受此限制。

当前阈值集中在 `src/word/web-safety.ts`：20000 个文字字符（按 JavaScript UTF-16 长度）、500 个正文段落、单次 OOXML 导出 2000000 UTF-8 字节。它们是首版产品限制，不是微软 API 限制。任何图片均不放行，因此多图片文档也被拦截。自动编号列表暂不放行，手工输入的列表符号属于普通文字。

空白页眉/页脚部件、空批注容器以及默认脚注/尾注分隔符不会仅因部件存在而触发拦截。页眉/页脚引用只有在分别检查各类页眉和页脚后才放行。普通页眉/页脚内容和空表格可以保留；仅判断文本为空是不够的，仍检查是否存在合并、嵌套及图片等结构。

表格分两步检查：先加载正文和六类页眉/页脚的 `tables.items/isUniform`、`nestingLevel`，行列不一致或嵌套级别大于 1 即拒绝；通过后仍扫描 OOXML。检查嵌套 `w:tbl`、`w:gridSpan`（仅允许 1）、`w:vMerge`、`w:hMerge`、省略单元格的 `gridBefore/gridAfter`、各行单元格数与 `tblGrid` 列数。`isUniform=true` 不代表没有合并。属性读取失败时停止翻译，不将失败当作 SAFE。

已用用户提供的 TEST ENG.docx 做本地结构验证：正文为 Hello Jason，六个页眉/页脚包含空三列表格；检查通过，生成译文 OOXML 后六个表格保持不变。对该样例注入合并与嵌套结构后均被拒绝。原文档未修改，未加入仓库。

检查在读取待翻译内容前、翻译服务返回后、原文备份保存后执行。无法导出或解析结构时停止，不降级为 HTML 检查。未知内容或格式默认拒绝。Office 检查和写入不是原子事务，这些检查不能保证同时协作编辑时绝无变化。

侧边栏持续显示手动备份提示；插件不自动创建副本，也不确认用户是否实际完成备份。桌面端自动生成翻译副本不属于本次实现。

## 实机验收（尚待执行）

- 在 Word Online 打开仅含普通段落、标题和加粗的 docx，验证空页眉/页脚的 OOXML 导出能通过检查，三个翻译入口均可使用。
- 插入普通表格和空表格，验证允许翻译；正文表格文字被翻译，行列结构和格式保留，恢复后原文可取回。
- 对表格横向合并、纵向合并、插入嵌套表格，分别验证拒绝；每行合并方式相同的表格也应拒绝。正文、首页、奇偶页页眉/页脚都覆盖。
- 插入图片、公式、超链接、修订、自动编号、内容控件，分别验证拒绝翻译且正文不变。即使只选择普通段落也应拒绝。
- 页眉/页脚普通文字和普通表格允许保留；图片、合并或嵌套结构拒绝。
- 验证超过任一阈值的文档被拦截；正文结构读取失败时显示桌面客户端指引。
- 翻译等待期间新增复杂结构，验证不写入译文；右键命令与按钮遵循同一限制。
- 验证网页版备份提示可见，桌面 Word 中提示隐藏，原有翻译和恢复流程可用。

空页眉导出若在某个宿主中失败，会保守拒绝网页版翻译，不能以省略检查的方式放行。正文范围导出不等同于完整 docx 文件，需通过上述实机用例验证目标宿主暴露的结构。
